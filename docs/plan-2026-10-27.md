# Plan: items 48–56 (noted 2026-10-27)

What each item is: README › Coming next. This file is the build plan: decisions, where the code
goes, order, risks. Removed once everything is built and confirmed (like the earlier plans).

## Rules for every batch

- Build test-first (`ecc:tdd-guide`); after the code `ecc:typescript-reviewer` +
  `ecc:react-reviewer` in parallel, `ecc:database-reviewer` + `ecc:security-reviewer` for each
  migration / RLS / Edge Function change, `ecc:e2e-runner` for the journeys, `ecc:doc-updater`
  for README.
- Migrations: dev first (`npx supabase db push --linked`), then prod
  (`bash scripts/db-push-prod.sh`) **before** the app code that needs them is pushed. Edge
  Functions: `bash scripts/deploy-functions.sh dev`, then `prod`.
- A cached query whose shape changes gets a new key version (like `RECIPES_SHAPE`), never
  `CACHE_BUSTER`. Each commit: patch-notes entry, README, `pnpm knip` clean.
- **One rule everywhere:** a cheat day, an alcohol day or a day missing lunch or dinner is never
  part of any figure (averages, within goal, saved calories, week page, notifications).

the calendar (`calendar.ts dayStatus`) and Trends' "within goal" (`trends.ts atGoal`), so they
agree. Appearance › over colors: labels "More than 10 % over" / "More than 300 kcal over",
footer "Only calories change color", preview sample updated. Stored `{mode, full, well}` keeps
its shape. Note: with a goal above 3,000 kcal, 300 kcal over is reached before 10 %, so the
ring goes straight to red (as decided). Tests pinning 1.1 / carbs / fat are rewritten.

**51. Weight per unit vs values per unit.** Scanning fills in only what Open Food Facts states
(`openFoodFacts.ts productPrefill` uses the reported values, no `completeBases`); the
"worked out from…" tests are turned around. Two new form checks in `ingredients/valueChecks.ts`:
weight per unit filled but no values per unit, and values per unit without a weight; shown in

## Risks

| Risk                                                          | Mitigation                                                                                      |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Changing `daily_totals` / cached month rows breaks old caches | new column at the end of the view, month/trends query keys versioned                            |
| Placeholder lines reach `save_dish`                           | blocked in `saveError`; the DB's `> 0` checks stay as a backstop                                |
| Old phone drafts dropped by a stricter draft schema           | marker optional, existing drafts parse as before (test with a stored v1 draft)                  |
| App and push-tick counting days differently                   | one shared `dayCounting` in `_shared`, tested once                                              |
| Drag to reorder fighting the back swipe / tab swipe           | handles only start a drag; the same rule as sliders (point 23)                                  |
| History getting crowded on 390 px                             | symbols tiny and in fixed corners, key explains them; checked against the user's iPhone numbers |
