# Plan: items 57–68 (noted 2026-10-29)

Decisions come from the user's answers on 2026-10-29. Order H → I → J → K → J2; each push is
built, pushed, and the user tests it on the iPhone.

## Rules for every batch

- Built test-first (`ecc:tdd-guide`, parallel only on separate files); then `ecc:typescript-reviewer` and
  `ecc:react-reviewer` (plus `ecc:database-reviewer` / `ecc:security-reviewer` for SQL, RLS, RPCs,
  Edge Functions; `ecc:silent-failure-hunter` for new error paths; `ecc:e2e-runner` for journeys);
  one agent fixes the findings; typecheck, tests, knip and the journeys (built against dev) run
  before the push.
- Migrations: dev first, `pnpm db:types`, then prod (`bash scripts/db-push-prod.sh`) before any app
  code that needs them is pushed.
- Patch note + README in the same commit. `CACHE_BUSTER` never; a cached query whose shape changes
  gets a new key version.
- Gym, sex, vegan and halal never enter counting (`dayCounting.isLeftOut`, `daily_totals`,
  push-tick, the review's counting) or any notification.

## J2 — later experiment (outline only): gym days from Apple Health

Gym days always stay settable by hand. Idea: an iOS Shortcuts automation at a fixed evening time
reads today's workouts from Apple Health (Lyfta writes there; the user's Fitbit doesn't by itself)
and posts to an Edge Function `gym-mark` with a personal token (hashed, revocable, rate-limited;
a mark removed by hand isn't set again). Settings › Gym days shows the token and the steps.
